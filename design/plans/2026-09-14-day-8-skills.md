> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the four agent skills, the `/analyze` command, and the toolbox routes they need, so the whole chain runs end to end on a fixture.

**Architecture:** Three new read/write routes join the CLI (`status`, `log-decision`, `suggest-base`); four existing behaviours are tightened where the adversarial review found guarantees that did not hold (`Plan.budget` gains a consumer and a freeze, `embed --timeout` becomes a cap, `embed` refuses a third attempt, the adapter's digest is recorded). **Tech Stack:** Python 3.12, numpy, scipy.sparse, scikit-learn 1.9.1, pydantic v2, pytest. Interpreter is `.venv/Scripts/python.exe` (Windows, Git Bash). Skills and command are Markdown.

**Spec:** `design/specs/2026-09-14-day-8-skills.md`

## Global Constraints

- **Refuse, never warn.** A contract violation raises `ContractError` and writes nothing. No override flag anywhere. `main()` maps it to exit code 2.
- **A refusal message must name its recovery route.** `cli.py` prints the message and nothing else; an agent with no stated next step loops.
- **The decision log is the authority, not the file.** Anything the freeze governs — outcomes, attempt counts, whether the re-plan round is spent — is derived from `decisions.jsonl`, which is append-only and predates every Embedding. Files can be deleted; the log cannot.
- **Add no second Budget.** `Plan.budget` at `drtools/plan.py:88` already exists and is the single authority. Do not add a `--budget` run argument, and do not record a Budget on the manifest.
- **`Amendment` is not implemented.** Refusals that would need one say so plainly.
- **Naming:** use `CONTEXT.md`'s terms. It lists "protocol", "config", "recipe", "guardrails", "audit trail" and others as words to avoid — check before introducing a term. Task 8 adds the three terms the skills need; tasks 10–14 must not invent vocabulary ahead of it.
- **Skill prose shape:** every `SKILL.md` has exactly four sections — `## Steps`, `## What to attend to`, `## Traps`, `## What to log`. Steps are exact numbered commands; judgment is briefed, never tabulated.
- **Existing decision-log stage names** are `recon`, `embed`, `rank`, `validate_plan`, `register_plan`. `profile` logs nothing. Do not rename them.
- Run the suite with `.venv/Scripts/python.exe -m pytest -q` (272 tests, ~60 s at the start of this plan).
- Commit messages are imperative and describe the guarantee, not the file. End each with the repository's attribution line.

# drtools/status.py
"""Where a run stands, derived rather than remembered.

`/analyze` resumes by asking this rather than by stat-ing files described in prose,
and every skill's first step reads its position from here. Existence comes from
artefacts. Anything the freeze governs — a candidate's outcome, how many attempts it
has had, whether the re-plan round is spent — comes from the decision log, which is
append-only and predates every embedding.
"""

from __future__ import annotations

from typing import Any

from drtools import jsonio
from drtools.runs import RunDir

MAX_ATTEMPTS = 2
"""One attempt plus the one diagnose-and-retry the design promises."""


def attempts(run: RunDir, candidate_id: str) -> list[dict[str, Any]]:
    """Every recorded attempt at one candidate, oldest first."""
    return [
        record
        for record in run.decisions()
        if record.get("stage") == "embed" and record.get("candidate") == candidate_id
    ]


def run_status(run: RunDir) -> dict[str, Any]:
    decisions = run.decisions()
    registered_path = run.path / "plan.registered.json"
    registered = registered_path.exists()
    plan = jsonio.read(registered_path) if registered else None

    manifest = (
        jsonio.read(run.manifest_path) if run.manifest_path.exists() else {}
    )

    candidates: dict[str, Any] = {}
    for candidate in (plan or {}).get("candidates", []):
        candidate_id = candidate["id"]
        tries = attempts(run, candidate_id)
        outcome = (tries[-1].get("outcome") or "crashed") if tries else None
        candidates[candidate_id] = {
            "outcome": outcome,
            "attempts": len(tries),
            "retry_available": outcome not in (None, "ok") and len(tries) < MAX_ATTEMPTS,
            "metrics": (run.path / "metrics" / f"{candidate_id}.json").exists(),
        }

    state = {
        "run_id": run.id,
        "seed": manifest.get("seed"),
        "budget": (plan or {}).get("budget"),
        "profiled": run.profile_path.exists(),
        "reconnoitred": run.recon_path.exists(),
        "registered": registered,
        "reference_prepared": (run.path / "data" / "reference.json").exists(),
        "ranked": (run.path / "ranking.json").exists(),
        "replan_round_spent": _replan_spent(decisions),
        "candidates": candidates,
    }
    state["next"] = _next_stage(state)
    return state


def _replan_spent(decisions: list[dict[str, Any]]) -> bool:
    """A registration recorded after a ranking is the one re-plan round, spent.

    The log is ordered, so position is the whole test. Before any ranking exists a
    re-registration is an ordinary retry, not a round.
    """
    stages = [record.get("stage") for record in decisions]
    if "rank" not in stages:
        return False
    first_rank = stages.index("rank")
    return "register_plan" in stages[first_rank + 1:]


def _next_stage(state: dict[str, Any]) -> str:
    if not state["profiled"]:
        return "profile"
    if not state["reconnoitred"]:
        return "recon"
    if not state["registered"]:
        return "plan"
    outstanding = [
        candidate_id
        for candidate_id, record in state["candidates"].items()
        if record["outcome"] is None
        or (record["outcome"] != "ok" and record["retry_available"])
    ]
    if outstanding or not state["reference_prepared"]:
        return "execute"
    scorable = [
        candidate_id
        for candidate_id, record in state["candidates"].items()
        if record["outcome"] == "ok" and not record["metrics"]
    ]
    if scorable or not state["ranked"]:
        return "evaluate"
    return "report"
```

def test_a_third_attempt_on_one_candidate_is_refused(cli, failing_run):
    """One attempt plus one retry is the whole allowance.

    Nothing counted attempts before this, so a loop of revise-and-retry could spend
    unbounded compute while the design claimed a single retry.
    """
    run = failing_run  # a run whose candidate "c1" has already failed twice
    result = cli("embed", "--run-dir", run, "--id", "c1", "--in-process")
    assert result.code == 2
    assert "two attempts" in result.stderr
    assert "new candidate id" in result.stderr


def test_an_interrupted_run_still_offers_the_retry(cli, one_failure_run):
    """A failed candidate has an Outcome, so "lacks an Outcome" would skip it.

    The failure must become permanent because the diagnosis was exhausted, never
    because the process died.
    """
    run = one_failure_run  # "c1" has failed exactly once
    status = cli("status", "--run-dir", run).payload
    assert status["candidates"]["c1"]["attempts"] == 1
    assert status["candidates"]["c1"]["retry_available"] is True

def _cmd_log_decision(args: argparse.Namespace) -> dict[str, Any]:
    """The agent's only route into the decision log.

    Every key is resolved before anything is written, and what it resolved to is
    written alongside it. Validating at write time and reading at report time are
    different guarantees: artefacts are rewritten in place, so a key can resolve to
    one value when a decision is logged and to another when the report reads it.
    Keeping the reading makes that divergence detectable instead of invisible.
    """
    run = _require_run(args)
    document = _read_json_argument(args.json)
    if not isinstance(document, dict):
        raise ContractError("--json must be a JSON object describing one decision.")

    missing_fields = [
        field for field in ("stage", "question", "chosen", "rationale")
        if not document.get(field)
    ]
    if missing_fields:
        raise ContractError(
            f"the decision is missing {', '.join(missing_fields)}. A decision records "
            "what was asked, what was chosen and why; a record without them cannot be "
            "reported from."
        )

    evidence = list(document.get("evidence") or [])
    artifacts = _artifacts_for_evidence(run)
    resolved = resolve_evidence(evidence, artifacts)
    unresolved = [key for key, value in resolved.items() if value is MISSING]
    if unresolved:
        raise ContractError(_unresolved_message(unresolved, artifacts))

    run.log_decision(
        stage=document["stage"],
        question=document["question"],
        chosen=document["chosen"],
        rationale=document["rationale"],
        evidence=evidence,
        options_considered=document.get("options_considered") or [],
        evidence_resolved=jsonio.jsonable(resolved),
        **{
            key: value for key, value in document.items()
            if key not in {
                "stage", "question", "chosen", "rationale", "evidence",
                "options_considered", "evidence_resolved",
            }
        },
    )
    return {"logged": document["stage"], "evidence_resolved": jsonio.jsonable(resolved)}


def _artifacts_for_evidence(run: RunDir) -> dict[str, Any]:
    """Everything an evidence key may cite, keyed by its artefact-root name."""
    artifacts: dict[str, Any] = {}
    for name, path in (
        ("profile", run.profile_path),
        ("recon", run.recon_path),
        ("plan", run.plan_path),
        ("ranking", run.path / "ranking.json"),
    ):
        if path.exists():
            artifacts[name] = jsonio.read(path)
    registered = run.path / "plan.registered.json"
    if registered.exists():
        artifacts.setdefault("plan", {})
        artifacts["plan"] = {**artifacts.get("plan", {}),
                             "registered": jsonio.read(registered)}
    return artifacts


def _unresolved_message(unresolved: list[str], artifacts: dict[str, Any]) -> str:
    """Name the broken key and the keys that do exist beside it.

    An agent told only that something failed will guess again; told what is there, it
    corrects.
    """
    lines = []
    for key in unresolved:
        parent = key.rsplit(".", 1)[0]
        siblings = resolve_evidence([parent], artifacts)[parent]
        available = (
            ", ".join(sorted(siblings)) if isinstance(siblings, dict) else "nothing"
        )
        lines.append(f"  {key} — {parent} holds: {available}")
    return (
        "these evidence keys do not resolve against this run's artefacts:\n"
        + "\n".join(lines)
        + "\nCite a key that exists, or drop it: an empty evidence list is allowed and "
        "renders as unsupported, but a citation pointing at nothing is a broken "
        "rationale."
    )
```

Frontmatter:

```yaml
---
name: profile-dataset
description: Measure an unfamiliar dataset and gather structural evidence before any analysis is planned. Use when starting a dr-agent run.
---
```

Four sections, in this order.

**`## Steps`** — exact commands:
1. `drtools status --run-dir <R>` when resuming; skip on a fresh Run.
2. `drtools profile --data <spec> --runs-root runs --run-id <id>` — or `--run-dir <R>` when the Run exists.
3. If loading is refused, take the adapter route below, then repeat step 2.
4. `drtools recon --run-dir <R>`. Do not pass `--k` or `--max-samples`: they exist, and tuning the probes that justify your own Plan is not evidence.
5. Read `figures/recon_thumbnail.png` as an image.
6. `drtools log-decision` once per judgment reached.

**`## What to attend to`** — the `observations` in both artefacts are statements about what the numbers imply, not the numbers. Restating a measurement is not a decision. What earns a record is a reading: what the sparsity and the spread of sample totals together mean for whether raw distances measure anything; whether the spectrum's decay says the structure is largely linear; what the graph's component count rules out before it is tried.

**`## Traps`**
- An intrinsic dimension near the ambient dimension is not evidence of nothing until the neighbourhood graph's connectivity has been checked.
- Every reconnaissance number is conditional on the Probe representation. Say which one, and say that the Probe representation is not the analysis.
- A Loader that refuses missing values or string labels is refusing on purpose. Imputation is a decision to log, not a default to reach for.
- Where the spectrum was computed on both raw and probe, the difference between them is itself the cheapest evidence about whether preprocessing matters here.

**`## What to log`** — the adapter decision when one was written, naming what the built-in Loaders refused; one decision per reading, citing keys under `profile.` and `recon.`. Available roots: `profile`, `recon`. A key that does not resolve is refused, and the refusal names the keys that do exist.

**`## The open adapter`** — a subsection under Steps. When `drtools datasets` lists nothing that recognises the input, write `runs/<id>/adapter.py` exposing `load(path, **kwargs) -> (X, labels, meta)` and pass `--adapter runs/<id>/adapter.py`. It lives inside the Run so the Run stays self-contained. The Loader contract checks the data that comes back; it does not check what the module did on the way, so write nothing that touches anything outside the Run.

### Task 11: Skill — `plan-analysis`

**REQUIRED SUB-SKILL:** use `writing-for-agents`.

**Files:**
- Create: `.claude/skills/plan-analysis/SKILL.md`

**Interfaces:**
- Consumes: `drtools status`, `drtools methods`, `drtools suggest-base`, `drtools suggest-params`, `drtools validate-plan`, `drtools log-decision`
- Produces: `plan.json`, `plan.registered.json`, decision records at stages `plan`, `validate_plan`, `register_plan`

- [ ] **Step 1: Write the skill**

```yaml
---
name: plan-analysis
description: Choose the candidate pipelines, the rejections, and the pre-registered weighting for a dr-agent run, then register the plan. Use after profiling.
---
```

**`## Steps`**
1. `drtools status --run-dir <R>`. If it reports `registered: true`, you are in the second round — read that section instead.
2. Read `profile.json` and `recon.json` from the Run. Not from memory.
3. `drtools methods` for the Capability records; `drtools methods --op <op>` for one in full.
4. `drtools suggest-base --run-dir <R>`. Adopt it, or override it and log why.
5. `drtools suggest-params --run-dir <R> --op <op>` for each Reduction under consideration.
6. Write `plan.json` into the Run.
7. `drtools validate-plan --run-dir <R>`. On refusal, log the refusal, revise from the message, resubmit. Repeat until it registers.
8. `drtools log-decision` for the Base preprocessing, each Candidate, each Rejection, and the weighting.

**`## What to attend to`** — a Candidate is a Stage list, not a method name: nobody runs t-SNE on raw genes, and `pca -> umap` is the field-standard pipeline, which makes the intermediate's `n_components` a choice to justify. Span families deliberately — one linear baseline, one local-structure, one global-structure — because when they disagree, the disagreement is itself the finding. A Rejection with a reason and a cited key is evidence of judgment in a way that running the method anyway is not. The weighting is argued from the user's instruction and the Profile, before any Embedding exists.

**`## Traps`**
- **The weighting is the one irreversible choice in the Run.** Once `validate-plan` registers, it cannot move: Amendment has no mechanism, and a changed weighting means a new Run. Get it right before registering, not after seeing results.
- The Base preprocessing is equally frozen, because every Candidate is scored against its output.
- Every Plan must include a Candidate ending in plain PCA. Without a linear baseline, "this data needs a manifold method" cannot be supported.
- A terminal method cannot feed another Stage, and a Candidate must end in a Reduction.
- A subsample below what the registered neighbourhood size supports will be refused at evaluation, so it is a planning-time constraint.
- Setting a parameter an op does not declare is an error, not a no-op.

**`## The second round`** — when `status` reports a registered Plan, you may add Candidate ids and revise Candidates that failed, timed out or crashed. Nothing else: the weighting, the Base preprocessing, and any Candidate that already succeeded are frozen, and a Candidate that ran and lost cannot be removed. A variant of a successful Candidate needs a new id. This round is where a sweep over the top-ranked Candidate's parameters belongs, and it happens at most once.

**`## What to log`** — one decision per Candidate and per Rejection, each citing keys. Every `validate-plan` refusal, with what was proposed and what it was revised to: that record is what lets the report say the loop worked.

### Task 12: Skill — `execute-plan`

**REQUIRED SUB-SKILL:** use `writing-for-agents`.

**Files:**
- Create: `.claude/skills/execute-plan/SKILL.md`

**Interfaces:**
- Consumes: `drtools status` (the `candidates` block from Task 1, including `attempts` and `retry_available`), `drtools prepare-reference`, `drtools embed`, `drtools validate-plan`, `drtools log-decision`
- Produces: `embeddings/`, `data/reference.json`, decision records at stage `execute`

- [ ] **Step 1: Write the skill**

```yaml
---
name: execute-plan
description: Run every candidate in a registered plan, diagnosing and retrying a failure once. Use after a plan is registered.
---
```

**`## Steps`**
1. `drtools status --run-dir <R>`.
2. `drtools prepare-reference --run-dir <R>` unless `reference_prepared` is already true.
3. For each Candidate whose `outcome` is `null`, **or** whose `outcome` is not `ok` and whose `retry_available` is true: `drtools embed --run-dir <R> --id <candidate>`.
4. Do not pass `--timeout`. It defaults to the registered Budget's cap, and a value above that cap is refused.
5. On a non-`ok` outcome, read `embeddings/<id>.json` and take the retry below.
6. `drtools log-decision` for each diagnosis and each permanent failure.

**`## The retry`** — a subsection under Steps, because step 5 has nowhere else to go.

Registration is a toolbox event, not another skill's property: re-register here rather
than handing back to `plan-analysis`. The freeze governs what any caller may change, so
routing through a different skill buys nothing, and it would conflate the per-Candidate
retry with the once-per-Run re-plan round.

1. Read `embeddings/<id>.json`: the exception type, the Stage that raised, the
   parameters it ran with.
2. Decide the repair. Either revise the failed Candidate's Stages in `plan.json`, or add
   a new Candidate id for a differently-shaped attempt.
3. `drtools validate-plan --run-dir <R>` to register the revision.
4. `drtools embed --run-dir <R> --id <candidate>`.
5. `drtools log-decision` naming the exception, the repair and its outcome.

Revising a Candidate that failed is permitted; revising one that succeeded is refused,
and so is dropping one that ran and lost.

**`## What to attend to`** — the failure record names the exception type, the Stage and the parameters it ran with, which is what a repair is built from. `MemoryError` and `LinAlgError` want different repairs. A `timeout` did not fail: it did not finish, and the honest reading is sometimes that the method does not fit this Budget rather than that it needs another try. The diagnosis is the judgment here, and a report sentence naming what failed, what was changed and what happened next is the clearest evidence of agency the Run produces.

**`## Traps`**
- **Read `retry_available`, not whether an Outcome exists.** A failed Candidate has an Outcome. Skipping it because it has one would make a failure permanent because a process died rather than because the diagnosis was exhausted.
- Two attempts is the whole allowance. A third on the same id is refused; register a new id for a further variant.
- A Candidate that already succeeded is frozen. A variant needs a new id, not revised Stages.
- Raising the Budget to rescue a timeout is refused, because every Candidate was planned under the registered one.
- A permanent failure is recorded and the rest of the portfolio continues. One method failing is not the Run failing.

**`## What to log`** — the diagnosis, naming the exception and the Stage; what was changed and why; the permanent failure when the allowance is spent. Cite keys under `plan.registered.` and the Candidate's own outcome record.

Run: `.venv/Scripts/python.exe -m pytest tests/test_status.py -q` then read the payload shape in `drtools/status.py`
Expected: `outcome`, `attempts`, `retry_available`, `metrics` and `reference_prepared` all appear, spelled as the skill spells them.

### Task 13: Skill — `evaluate-embeddings`

**REQUIRED SUB-SKILL:** use `writing-for-agents`.

**Files:**
- Create: `.claude/skills/evaluate-embeddings/SKILL.md`

**Interfaces:**
- Consumes: `drtools status`, `drtools evaluate`, `drtools rank`, `drtools figures`, `drtools log-decision`
- Produces: `metrics/`, `ranking.json`, `figures/`, decision records at stage `evaluate`

- [ ] **Step 1: Write the skill**

```yaml
---
name: evaluate-embeddings
description: Score every embedding a run produced, rank them under the registered weighting, draw the figures and read them. Use after candidates have run.
---
```

**`## Steps`**
1. `drtools status --run-dir <R>`.
2. For each Candidate whose `outcome` is `ok` and whose `metrics` is false: `drtools evaluate --run-dir <R> --id <candidate>`.
3. `drtools rank --run-dir <R>`.
4. `drtools figures --run-dir <R>`.
5. **Look at the figures.** Read the rendered PNGs as images, the small-multiples panel first.
6. `drtools log-decision` for the reading, and for whether a re-plan round is warranted — recorded either way.

**`## What to attend to`** — the ranking is a weighted combination of an absolute-scale Battery, so a winner is not thereby good; check the scores, not only the order. Where a Reference value is reported, read the Embedding against it. When `rank` says a metric was dropped and weight redistributed, that changed what the weighting means and the report has to say so. The figures are evidence, not decoration: a collapsed embedding, a class that never separates, a panel that disagrees with its metrics are all things visible only by looking.

**`## Traps`**
- t-SNE cluster sizes and inter-cluster distances are not meaningful. Do not interpret them.
- A Reference value is a baseline, not a ceiling. An Embedding can exceed it, and that is real: in high dimensions distances concentrate, so discarding noisy directions can recover structure the full space obscured. Do not report it as an error, and do not divide through to express it as a percentage.
- A failed Candidate is excluded from the ranking rather than scored zero. Zero would rank the method; what failed was one configuration of it.
- The figures record which rendering regime they used. Points and a density field are different things to be looking at.

**`## The re-plan round`** — at most once per Run, and only when there is a reason: a family unrepresented because its Candidate failed, a winner close enough to the baseline to be worth probing, a parameter the metrics suggest. It can only add Candidate ids. If the weighting itself now looks misjudged, that cannot be fixed within this Run — log it as a finding so the report says so plainly, and do not attempt a re-registration that will be refused.

**`## What to log`** — the reading of the ranking, citing keys under `ranking.`; the re-plan decision either way, with its reason.

- Produces: the entry point. On day 8 it stops after evaluation, because `write-report` does not exist.

- [ ] **Step 1: Write the command**

```yaml
---

---
```

Body, in this order:

**Arguments.** `$ARGUMENTS` holds the dataset spec, optionally followed by `--auto`, `--budget fast|standard|thorough` (default `standard`), and `--run-dir <R>` to resume.

**The sequence.** Numbered, each step naming the skill to invoke and the Run directory to pass:
1. When `--run-dir` was given, `drtools status --run-dir <R>` and enter at the stage its `next` field names. Otherwise start at step 2.
2. Invoke `profile-dataset`.
3. Unless `--auto`: one checkpoint, at most two multiple-choice questions, each stating a default and proceeding on that default if unanswered. Ask only what the profile made genuinely open — never as a formality.
4. Invoke `plan-analysis`. The Budget from `--budget` goes into the Plan's `budget` field, which is frozen at registration.
5. Invoke `execute-plan`.
6. Invoke `evaluate-embeddings`.
7. If it logged that a re-plan round is warranted and `status` reports `replan_round_spent: false`, invoke `plan-analysis`, then `execute-plan`, then `evaluate-embeddings` once more. At most once.
8. Stop. Print the Run directory path and say plainly that the report stage is not built yet, so the analysis is complete but unwritten.

**What this command does not do.** It does not read artefacts itself or make analysis decisions; each skill reads its own state from the Run. A skill is invoked, not inlined.

**Why step 8 says so out loud.** A chain that ends quietly after evaluation is indistinguishable from a finished analysis. Saying the stage is missing is the difference between an incomplete Run and a Run that looks complete.
